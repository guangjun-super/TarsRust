# TarsRust 服务注册与发现设计

## 目标与范围

参照本机 `/Users/chengj/Developer/repo/TarsGo` 的行为，将现有 Registrar、Communicator、ServantProxy 与 Application 连通，使平台配置的 Rust 服务可以通过对象名被发现，并随平台端点变化持续更新路由。

保留现有同步 `string_to_proxy` 和生成代码接口。已有 `Obj@tcp ...` 直连方式继续可用。此次不增加非标 UDP 服务端、UDP RPC 传输、TLS 或新的注册中心产品。

## Go 行为依据

- `tars/registry/tars/registry.go`：原生 Registry/Deregister 无操作；默认 SameGroup，启用 SET 时 SameSet；非零查询返回码是错误。
- `tars/registry.go`：自定义注册器收到每个业务适配器的完整实例信息；注册、注销错误记日志并继续处理其他适配器。
- `tars/endpointmanager.go`：首次查询、缓存回退、周期刷新；刷新错误或空活跃列表保留旧节点；健康检查、恢复探测及按调用选择 Hash。
- `tars/communicator.go`：Locator、SET 开关、SET 分组参与路由隔离。
- `tars/protocol/res/queryf/QueryF.tars.go`：SameGroup 输出标签为 2/3，SameSet 为 3/4。

## 组件与数据流

### 原生注册及自定义注册器

原生 Tars 服务上线仍使用现有平台配置与 tarsnode 心跳，不向 QueryF 发明注册 RPC。明确文档中的 Registrar 原生无操作语义。

为 Application 和 Communicator 提供自定义 `Arc<dyn Registrar>` 注入入口。应用级注入同时供客户端发现使用；仅客户端也可独立注入。

业务监听器全部就绪后，为每个业务适配器调用 register；退出时，在关闭业务监听器前调用 deregister。实例包括版本、应用、服务名、完整 servant 对象名、SET 信息、协议及实际监听端点。动态端口使用绑定后的端口；管理适配器不作为业务实例注册。

与 Go 一致，注册失败只记录错误并继续启动、继续注册其他实例；注销失败只记录错误并继续退出。各次回调受有限超时约束，不能无限阻塞生命周期。

### 客户端发现

直连对象不创建发现任务。裸对象名有自定义 Registrar 时使用它，否则根据配置 Locator 创建原生 TarsRegistry；既无 Locator 也无自定义注册器时返回明确配置错误。

`string_to_proxy` 仍同步返回代理，不阻塞 Tokio runtime。首次异步调用前进行查询，使用异步互斥避免并发首次调用重复初始化。首次发现失败且无缓存时将错误传递给调用者，后续调用能够重试。

首次查询后，由代理维护刷新任务；任务不能通过强引用使代理永久存活，代理释放或显式关闭后停止。查询、刷新与业务调用均不得在持有同步锁时 await。

代理缓存标识包含对象名、Locator、SET 开关及分组；更改配置后新建的代理使用新配置，已有代理维持创建时的路由身份，避免跨注册中心或 SET 混用。

Application 的平台 SET 配置同步到 Communicator。未启用 SET 时 SameGroup，启用时 SameSet 并传递 setdivision。

### QueryF 协议与注册中心故障切换

请求中的 servant name 使用 Locator 中的对象名。检查 RPC 返回码以及业务返回码 tag 0；使用方法对应的输出标签解码。

一个查询对每个候选注册中心地址最多尝试一次，使用现有熔断状态轮转选择；不因索引变化漏掉候选。网络操作必须支持取消，超时不遗留后台阻塞 socket 读取。

保留 EndpointF 到内部 Endpoint 可表达的字段；权重、权重类型、SET 信息不得丢失。地址相同而元数据变化时也要更新路由信息。

### 刷新和磁盘缓存

使用 `refresh_endpoint_interval` 周期刷新。成功得到非空活跃列表后更新选择器及适配器，移除失效端点并关闭对应连接。失败或活跃列表为空时保留上一份可用列表，与 Go 一致；首次查询为空且无缓存时调用返回无可用服务。

应用使用 data_path 下服务名对应的 `.tarsdat` 文件持久化发现结果；独立客户端可显式配置缓存路径，未配置时不写文件。缓存身份包括对象名、Locator、SET 开关与分组。缓存用于首次实时查询失败时回退，实时查询成功优先于缓存。

缓存损坏、文件缺失、写入失败只记录日志，不能破坏已取得的端点。采用原子替换写入，多个对象的更新保留同一文件内其他对象记录。Rust 缓存格式需包含版本号；本次不承诺读取 Go 的历史缓存文件。

### 路由和业务节点健康

将 AdapterProxy 已有失败计数、健康状态和恢复间隔接入实际选路。普通请求使用轮询及静态权重，Hash 请求按消息的 hash 类型使用 ModHash 或一致性 Hash。

不健康适配器从正常选择集合剔除，到现有恢复间隔后允许探测；成功则 reset 并恢复选择，失败则继续隔离。注册中心仍标记活跃但本地全部不健康时，按照 Go 的回退策略允许选择注册中心活跃节点，防止永久无请求、无法恢复。

直连节点也参与健康管理。节点恢复与失败统计覆盖普通调用和 oneway；oneway 的成功只能表示发送成功。保留现有健康判定阈值，避免本次额外改变故障策略。

## 验收与验证

1. 假 QueryF 服务验证 SameGroup、SameSet 方法、参数、输出标签、业务错误码及自定义 Locator 对象名。
2. 至少两个注册中心节点验证故障切换覆盖所有候选、查询超时可取消。
3. 对象名创建代理后可真实调用；并发首次调用只初始化一次；动态刷新后流量转向新节点。
4. SET 与 Locator 不同的代理、缓存不得串用；已有生成代码和直连测试继续通过。
5. 刷新失败、空列表保留旧端点；冷启动查询失败可用匹配缓存，损坏缓存正常报查询错误。
6. 验证权重、两种 Hash、故障剔除、恢复成功及全部不健康时的回退。
7. 自定义注册器验证就绪后注册、关闭前注销、完整实例信息和回调失败不阻断生命周期。
8. 验证代理释放不会遗留刷新任务，元数据变化能被应用；执行 workspace 回归及针对新增代码的静态检查。
9. 使用 Go QueryF 编解码或服务进行协议互通验证；真实 tarsnode 平台发布验证需要可用平台环境，不能用假服务测试替代宣称。

## 实施约束

沿用仓库现有 Rust/Tokio/Serde 技术栈，优先复用 EndpointManager、Selector 与 AdapterProxy，不引入第二套并行路由体系。仅为以上行为增加必要接口与配置。

实现按 QueryF、发现与缓存、选路健康、应用生命周期分别形成可测试的改动；完整功能验证后生成 commit。没有实际创建和合并临时工作树或分支时，无需执行清理。
